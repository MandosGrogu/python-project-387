# Тикет 007: Описание ошибок и граничных случаев

## Question

Как спецификация должна описывать ошибки (400, 404, 409, 422) и граничные случаи (прошедшее время, смена часового пояса, переход на летнее время)?

## Blocked by

[Тикет 001: Канонический формат спецификации](001-canonical-format.md)

## Type

grilling

## Resolution

- Универсальная схема ошибки в секции `components`, ссылки через `$ref` вместо дублирования для каждого эндпоинта.
- Механизм `examples` внутри конкретных путей (`paths`), чтобы фронтенд видел, какие `error_code` приходят при разных статусах.
- Формат `date-time` жёстко зафиксирован — время передаётся со смещением.
- Ограничения, связанные с DST, прописываются текстом в `description` схемы или эндпоинта (логика DST невозможна в JSON).
- Локальный контекст пользователя (часовой пояс) передаётся в кастомном заголовке или теле запроса по справочнику IANA (tz database).
