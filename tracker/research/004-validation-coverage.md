# Research 004 — Покрытие правил валидации в спецификации

**Дата:** 2026-09-29
**Источники:** `bookings/forms.py`, `bookings/models.py`, `docs/openapi.yaml`
**Примечание:** файл `docs/specification.md` в репозитории отсутствует. Сравнение выполнено только с `docs/openapi.yaml`.

## 1. Правила валидации из кода

### 1.1. BookingForm (bookings/forms.py)

| # | Правило | Код | Сообщение об ошибке |
|---|---------|-----|---------------------|
| V1 | Запрет выходных дней (сб, вс) | `clean_date`: `booking_date.weekday() >= 5` | «В выходные бронирование недоступно» |
| V2 | Время кратно 30 минутам | `clean_time`: `booking_time.minute not in (0, 30)` | «Время должно быть кратно 30 минутам» |
| V3 | Время в пределах рабочих часов | `clean_time`: `WORKING_HOURS_START <= time < WORKING_HOURS_END` | «Время должно быть в рабочие часы (9:00–18:00)» |
| V4 | Запрет прошедшего времени | `clean`: `booking_datetime <= timezone.now()` (только при создании, `instance.pk is None`) | «Нельзя запланировать звонок на прошедшее время» |
| V5 | Слот не занят | `clean`: `Booking.objects.filter(date, time).exists()` (исключая текущую запись при редактировании) | «Слот уже занят» |

## 3. Что описано неполно

| # | Проблема | Детали |
|---|----------|--------|
| G1 | Граница рабочих часов | В коде проверка `time < WORKING_HOURS_END` (строго меньше 18:00). В openapi.yaml указано «9:00–18:00» без уточнения, что 18:00 исключено. |
| G2 | Проверка прошедшего времени только при создании | В коде V4 применяется только при `instance.pk is None`. В описании PUT сказано «Редактирование прошедшего бронирования разрешено», но в общем списке `ValidationError` это не уточнено. |
| G3 | Исключение текущей записи при проверке занятости | В коде V5 при редактировании текущая запись исключается из проверки. В описании PUT это есть («Проверка занятости слота исключает текущее бронирование»), но для POST не явно указано, что проверка абсолютная. |
| G4 | Формат времени | `pattern: '^\d{2}:\d{2}$'` не гарантирует кратность 30 минутам. Кратность описана только текстом в `ValidationError.description`. |
| G5 | Отсутствующий файл | `docs/specification.md` не существует. Если он планировался как источник спецификации — его нужно создать либо удалить упоминание. |

---

## 4. Рекомендации

1. **Уточнить границу рабочих часов** в `openapi.yaml`: заменить «9:00–18:00» на «с 9:00 до 18:00 (18:00 исключено)» или добавить `exclusiveMaximum`.
2. **Разделить описание ошибок для POST и PUT**: для PUT явно указать, что проверка прошедшего времени не применяется.
3. **Добавить `minLength`/`required` для строковых полей** — сейчас не указано, что `client_name` и `topic` не могут быть пустыми (Django `CharField` по умолчанию требует непустое значение).
4. **Создать `docs/specification.md`** либо удалить ссылки на него из документации/AGENTS.md, если файл не планируется.
5. **Добавить описание авто-генерации `recording_url`** в спецификацию (сейчас поле есть в `Booking`, но логика генерации не описана).
6. **Уточнить формат времени**: вместо `pattern: '^\d{2}:\d{2}$'` можно использовать `pattern: '^([01]\d|2[0-3]):[03]0$'` для гарантии кратности 30 минутам на уровне схемы.
